# Self Medical Record — API Documentation & Contract

This directory contains the formal API specifications and integration artifacts for the Self Medical Record backend.

## Files

1. **`openapi.yaml`**  
   OpenAPI 3.1.0 specification documenting all 24 production API endpoints, request/response models, validation rules, authentication schemes, and synthetic examples.
2. **`self-medical-record.postman_collection.json`**  
   Postman Collection v2.1 containing pre-configured requests grouped by module with environment variables.

---

## Authentication Mechanism

- **Bearer Token (Sanctum):**  
  Add `Authorization: Bearer <token>` in request headers for all protected endpoints.
- **Signed URLs:**  
  The endpoint `GET /api/calorie-estimation/image/{filename}` does NOT require a Bearer token. Instead, it requires valid URL signature parameters (`expires`, `signature`) generated by the backend and valid for 24 hours.

---

## How to Import into Postman / Insomnia

1. Open Postman.
2. Click **Import** > Select `docs/api/self-medical-record.postman_collection.json` or `docs/api/openapi.yaml`.
3. Set your collection variables:
   - `base_url`: `http://localhost/api` (or staging URL)
   - `token`: (Obtained after running `POST /api/login`)
4. Subsequent requests in the collection automatically inherit `{{token}}`.

---

## Android Client Integration Guidelines

1. **Date Timezone:**  
   Always parse dates using `Asia/Jakarta` (+07:00). All health records and dashboard charts are normalized to Western Indonesia Time.
2. **Encrypted Fields:**  
   The user's NIK and Phone are stored encrypted on the server and are purposefully omitted from JSON responses to protect PII.
3. **Food Calorie Estimation:**  
   The backend currently operates in simulated mode (`is_mock: true`). The data structure matches the production contract and will remain identical when live AI vision is plugged in.
